# Match priority decision

The untracked ADR-001 proposal mixes longest-per-start and longest-per-end examples. This implementation explicitly uses --match-mode all (default), longest-per-start, and leftmost-longest. For ab/bc/abc in abc: all keeps three; longest-per-start keeps abc@0 and bc@1; leftmost-longest keeps abc@0. Equal-length ties use configured pattern order. Adjacent intervals do not overlap.

Selection runs after the complete file result is available, so chunk boundaries do not affect selection. Canonical cached matches retain every match allowed by case/whole-word options; priority is a read-time view. Changing priority never destructively filters the index. This favors correctness and reusable caches over avoiding short-match generation.
